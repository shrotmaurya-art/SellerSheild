# Notes on TASK T3.7: Real Store Mail and Shipments Integration

## Summary
Task T3.7 completes the HTTP integration for real store outbound mail and backoffice shipment listing across `HttpStoreClient` and adds the standalone Phase 3 handshake verification script `scripts/handshake_phase3.py`.

## Key Implementations
1. **HttpStoreClient Extensions (`agent/src/sellershield_agent/store/http_client.py`)**:
   - `send_mail`:
     - Requires backoffice `ServiceContext` (`Role.service`) and strictly rejects customer bearer tokens with `StoreForbidden`.
     - Acquires service token (`executor` or `monitor`) with client credentials grant.
     - Passes `Authorization: Bearer <service_token>`, `X-Request-ID`, and `Idempotency-Key` headers.
     - Formats payload matching OpenAPI `SendMailRequest` schema (`to_addr`, `subject`, `body_text`, `channel: "email"`), without extraneous properties.
     - Mutating POST uses zero retries (`_execute_post`), adhering to KP-16.
     - Error mapping maps store envelopes to `StoreValidationError`, `StoreForbidden`, `StoreNotFound`, `StoreDuplicate`, `StoreIdempotencyMismatch`, `StoreUnavailable`, and `StoreTimeout`.
   - `list_shipments_for_monitor`:
     - Requires `ServiceContext` (`Role.service`) and strictly blocks customer tokens with `StoreForbidden`.
     - Acquires monitor service token with client credentials grant.
     - Passes `Authorization: Bearer <monitor_token>` and `X-Request-ID` headers.
     - Supports pagination `limit` and `cursor`.
     - Queries direct backoffice `/admin/shipments`; when store returns 404, gracefully falls back to `/admin/orders` + `/orders/{id}/shipment` resolving order `customer_id`.
     - Maps network exceptions and timeouts to `StoreUnavailable` and `StoreTimeout`.
2. **Phase 3 Handshake Script (`scripts/handshake_phase3.py`)**:
   - Runnable via `uv run python scripts/handshake_phase3.py` or from `agent/` as `uv run python ../scripts/handshake_phase3.py`.
   - Step 1: Dispatches an automated test email notification to customer C001 (`aarav.mehta@example.test`) using `HttpStoreClient.send_mail` with service credentials.
   - Step 2: Logs in as C001 to store API (`/api/v1/auth/login`) and queries `/mail/inbox`, confirming the message arrived in C001's inbox.
   - Step 3: Queries store shipments via `HttpStoreClient.list_shipments_for_monitor` using monitor credentials and prints total count and delayed shipments count.
   - Preserves token confidentiality: all tokens handled as `SecretStr`, zero secrets printed or logged (KP-13).
3. **Respx Contract Test Suite (`agent/tests/test_store_http_phase3.py`)**:
   - 15 unit and contract tests verifying headers, payload schemas, token isolation, error mappings, timeout mappings, zero-retry write behavior, and pagination fallback.
